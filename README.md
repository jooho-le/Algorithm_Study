- **전체 스터디 기간:** 8월 2일(일) ~ 11월
- **알고리즘 집중 학습 기간:** 8월 9일(일) ~ 10월 17일(토)

## 3. 진행 방식

### 월요일 ~ 수요일: 알고리즘 개념 설명 `매주 일정 논의`

매주 스터디원 중 **한 명을 랜덤으로 선정하여 해당 주차 카테고리의 개념을 설명한다.**

설명 방식은 자유롭게 선택할 수 있다.

- PPT 제작
- 노션 또는 문서 정리
- 코드 실습
- 화이트보드 설명

단순히 내용을 읽는 방식이 아니라, **나머지 두 명이 해당 알고리즘을 이해하고 문제에 적용할 수 있을 때까지 설명하는 것**을 목표로 한다.

예를 들어 정렬 카테고리의 경우 다음 내용을 다룰 수 있다.

- 버블 정렬
- 선택 정렬
- 삽입 정렬
- 퀵 정렬
- 병합 정렬
- 기수 정렬
- 각 정렬 알고리즘의 동작 원리
- 핵심 코드
- 시간 복잡도와 특징
- 알고리즘별 차이와 사용 상황

---

### 주중: 카테고리 문제 풀이

개념 설명이 끝난 뒤, 해당 주차의 프로그래머스 카테고리 문제를 각자 풀이한다.

- 한 주 안에 해당 카테고리의 문제를 모두 푸는 것을 원칙으로 한다.
- 프로그래밍 언어는 각자 원하는 언어를 사용한다.
- 풀이 코드는 개인 이름으로 생성된 Git 브랜치에 업로드한다.
- 정답 코드를 그대로 복사하지 않고, 자신의 풀이 과정을 이해한 상태로 작성한다.
- 해결하지 못한 문제도 시도한 코드와 접근 방식을 정리하여 공유한다.

---

### 금요일 ~ 일요일: 문제 풀이 발표 `매주 일정 논의`

해당 주차의 **개념 설명 담당자**가 카테고리 문제의 풀이를 정리하여 설명한다.

문제 설명은 다음 순서로 진행한다.

#### 1. 적용 알고리즘 설명

문제 풀이에 사용된 알고리즘이나 자료구조의 핵심 개념을 간단히 설명한다.

#### 2. 문제 접근 방식 설명

- 문제에서 요구하는 내용
- 어떤 조건을 확인했는지
- 해당 알고리즘을 선택한 이유
- 해결 과정을 어떻게 설계했는지

#### 3. 기본 코드 설명

처음 문제를 해결한 코드의 전체적인 구조와 주요 로직을 설명한다.

#### 4. 개선 코드 설명

기본 코드에서 불필요한 연산이나 중복 코드를 줄인 경우, 개선 전후의 차이를 설명한다.

개선 코드가 없다면 기본 코드만 설명해도 된다.

#### 5. 복잡도 분석

가능한 경우 다음 내용을 정리한다.

- 시간 복잡도
- 공간 복잡도
- 입력 크기가 커졌을 때 발생할 수 있는 문제

복잡도 계산이 어려운 경우에는 프로그래머스의 **실행 시간 및 메모리 사용량 결과를 캡처하여 대체할 수 있다.**

#### 6. 사용 라이브러리 정리

문제 풀이에 사용한 주요 라이브러리나 내장 함수를 정리한다.

예시:

- Python `collections`
- Python `heapq`
- Java `HashMap`
- Java `PriorityQueue`

단순히 함수 이름만 적지 않고, 문제에서 어떤 목적으로 사용했는지 함께 설명한다.

#### 7. 문제 풀이 회고

다음 내용을 자유롭게 공유한다.

- 문제에서 가장 어려웠던 부분
- 처음에 잘못 접근했던 방식
- 구현하려고 했지만 실패한 방법
- 다른 풀이와 비교했을 때 자신의 풀이가 가진 장단점
- 다시 푼다면 개선하고 싶은 부분

## 4. Git 브랜치 운영 규칙

각 스터디원은 자신의 이름으로 된 브랜치를 사용한다.

```
main
├── 이주호
├── 전진욱
└── 박소현
```

카테고리별 폴더를 생성하여 풀이 코드를 정리한다.

```
이름/
├── hash/
├── stack_queue/
├── heap/
├── sorting/
├── brute_force/
├── greedy/
├── dynamic_programming/
├── dfs_bfs/
├── binary_search/
└── graph/
```

각 문제 파일에는 가능하면 다음 내용을 포함한다.

- 문제 이름
- 문제 링크
- 풀이 코드
- 사용 알고리즘
- 시간 복잡도
- 풀이 과정 또는 주석
